# Лаба №3 — шпаргалка (DriveNext)

## О чём лаба
Продолжаем то же приложение. В лабе 3 появляется **главный экран с нижним меню**, список машин с сервера, поиск, настройки и профиль:

| Экран | Что делает |
|---|---|
| **Главная** (`HomeFragment`) | Поле поиска, «Давайте найдем автомобиль», список карточек машин (RecyclerView) с сервера. Лоадер, ошибка + «Повторить» |
| **Результаты поиска** (`SearchResultsFragment`) | Машины по запросу (марка или модель), «Назад», поле с запросом — при изменении список обновляется |
| **Настройки** (`SettingsFragment`) | Аватар, имя, почта → «Профиль»; меню: Мои бронирования, Тема, Уведомления, Подключить свой автомобиль, Помощь, Пригласи друга |
| **Профиль** (`ProfileFragment`) | Аватар (по нажатию — загрузить новый), имя, «Присоединился в …», почта, «Поменять пароль», пол, Google, «Выйти из профиля» |
| **Нижнее меню** (`MainActivity`) | Главная / Избранное / Настройки — `BottomNavigationView` + меню `res/menu/bottom_nav.xml` |

Технологии из методички: **SearchView** (`OnQueryTextListener`), **RecyclerView** (Adapter, ViewHolder, LayoutManager), **нижнее навигационное меню**. Плюс **Coil** — загрузка картинок по ссылке.

Кнопки «Забронировать», «Детали», «Мои бронирования», «Подключить свой автомобиль» и вкладка «Избранное» ведут на экраны из лаб 4–5 — пока там заглушка `ComingSoonFragment` («Этот экран появится в следующих лабораторных работах»).

## Схема переходов

```
 Login / Регистрация / Splash (есть токен)
                 │
                 ▼
 ┌──────────────────────── MainActivity ────────────────────────┐
 │  [ контейнер для фрагментов ]                                │
 │                                                              │
 │  Главная ──«Найти»──► Результаты поиска                      │
 │     │                      │                                 │
 │     └─ «Забронировать» / «Детали» ─► заглушка (лаба 4)       │
 │                                                              │
 │  Настройки ──профиль──► Профиль ──«Выйти»──► Login (стек     │
 │     │                                         очищен)        │
 │     └─ Мои бронирования / Подключить авто ─► заглушка        │
 │                                                              │
 │  [ 🏠 Главная | 🔖 Избранное | ⚙ Настройки ]  ← нижнее меню  │
 └──────────────────────────────────────────────────────────────┘

 Нет интернета при запросе ──► [ NoConnection ] ──сеть есть──► назад, запрос повторяется сам
```

- Вкладки — **фрагменты** в одной Activity. Нажатие на пункт меню очищает back stack и подставляет корневой фрагмент вкладки.
- «Результаты поиска» и «Профиль» кладутся **поверх** вкладки с `addToBackStack` — нижнее меню остаётся видно (как в макете), «Назад» возвращает на корень вкладки.
- «Назад» на вкладке «Настройки»/«Избранное» сначала переключает на «Главную», и только потом закрывает приложение.
- Повторное нажатие на текущую вкладку — вернуться к её началу.

## Ключевые куски кода

### 1. SearchView (`HomeFragment`, `SearchResultsFragment`)
```kotlin
binding.searchView.setOnQueryTextListener(object : SearchView.OnQueryTextListener {
    override fun onQueryTextSubmit(query: String): Boolean {   // нажали «Найти» на клавиатуре
        binding.searchView.clearFocus()                          // спрятать клавиатуру
        viewModel.onSearchSubmit(query)                          // → переход на «Результаты поиска»
        return true
    }
    override fun onQueryTextChange(newText: String): Boolean {  // каждая буква
        viewModel.onQueryChanged(newText)                        // (на экране результатов)
        return true
    }
})
```
- На **Главной** ищем по `onQueryTextSubmit` (окончательный запрос) → открывается «Результаты поиска», там лоадер и запрос к серверу.
- На **Результатах** — по `onQueryTextChange`, но не на каждую букву: ViewModel ждёт паузу 400 мс (`debounce`), а старый запрос отменяется (`loadJob?.cancel()`).
```kotlin
query.drop(1).debounce(400).onEach { load() }.launchIn(viewModelScope)
```
- Запрос хранится в `SavedStateHandle` → переживает поворот и перезапуск приложения; после перезапуска результаты **загружаются с сервера заново** (требование ТЗ).

### 2. Поиск на сервере (`CarRepositoryImpl`)
```kotlin
postgrest["cars"].select(Columns.raw("id,brand,model,...")) {
    filter {
        eq("is_available", true)
        words.forEach { word ->              // каждое слово запроса
            or {                              // встречается в марке ИЛИ в модели
                ilike("brand", "%$word%")
                ilike("model", "%$word%")
            }
        }
    }
    order("price_per_day", Order.ASCENDING)
}.decodeList<CarDto>()
```
`ilike` — поиск подстроки без учёта регистра (SQL `ILIKE`). «mercedes sedan» найдёт Mercedes-Benz S 500 Sedan. Спецсимволы (`,`, `(`, `%`) из запроса вырезаются, чтобы не сломать фильтр.

### 3. RecyclerView + Adapter (`CarAdapter`)
```kotlin
class CarAdapter(...) : ListAdapter<Car, CarViewHolder>(CarDiff) {
    override fun onCreateViewHolder(parent: ViewGroup, viewType: Int) =     // создать карточку
        CarViewHolder(ItemCarBinding.inflate(LayoutInflater.from(parent.context), parent, false))
    override fun onBindViewHolder(holder: CarViewHolder, position: Int) =  // заполнить данными
        holder.bind(getItem(position))
}
// во фрагменте:
recyclerView.layoutManager = GridLayoutManager(context, resources.getInteger(R.integer.car_grid_columns))
recyclerView.adapter = adapter
adapter.submitList(state.cars)
```
- `ListAdapter` — это `RecyclerView.Adapter`, у которого `getItemCount()` уже реализован, а новый список сравнивается со старым через `DiffUtil` и перерисовываются только изменившиеся карточки.
- `GridLayoutManager` с 1 колонкой на телефоне = обычный вертикальный список; на планшете 2–3 колонки (адаптивная вёрстка).
- Фото машины — `ImageView.load(url)` из **Coil**: качает в фоне, кэширует, отменяет загрузку при переиспользовании ячейки. Пока фото нет — силуэт машины.

### 4. Нижнее меню (`MainActivity`, `res/menu/bottom_nav.xml`)
```xml
<menu>
    <item android:id="@+id/nav_home"      android:icon="@drawable/ic_nav_home"      android:title="Главная" />
    <item android:id="@+id/nav_favorites" android:icon="@drawable/ic_nav_favorites" android:title="Избранное" />
    <item android:id="@+id/nav_settings"  android:icon="@drawable/ic_nav_settings"  android:title="Настройки" />

```

```kotlin
binding.bottomNav.setOnItemSelectedListener { item -> showTab(item.itemId); true }
private fun showTab(itemId: Int) {
    supportFragmentManager.popBackStack(null, POP_BACK_STACK_INCLUSIVE)   // убрать вложенные экраны
    val fragment = when (itemId) { R.id.nav_settings -> SettingsFragment(); ...; else -> HomeFragment() }
    supportFragmentManager.commit { replace(R.id.container, fragment) }

```
В разметке: `app:menu="@menu/bottom_nav"`, `app:labelVisibilityMode="unlabeled"` (подписей нет, как в макете), `app:itemIconTint="@color/bottom_nav_item"` (селектор по `state_checked`).

### 5. Профиль: аватар и выход (`ProfileFragment`, `ProfileRepositoryImpl`)
- Нажатие на аватар → `PickVisualMedia` (как на шаге 3 регистрации) → фото грузится в `documents/<userId>/avatar.jpg` (`upsert = true` — заменяет старое) → в `users.avatar_path` пишется путь. Это и есть «Сохранение изменений профиля».
- Бакет `documents` приватный, поэтому для показа аватара берём **подписанную ссылку** на 1 час: `storage.from("documents").createSignedUrl(path, 1.hours)`.
- «Присоединился в июле 2024» — из `users.created_at`; месяц в предложном падеже из `string-array months_prepositional`; для женщин — «Присоединилась».
- «Поменять пароль» — письмо со ссылкой для смены пароля (`resetPasswordForEmail`).
- «Google» — почта из `user.identities` с provider = google, иначе «Не подключён».
- «Выйти из профиля» → `auth.signOut()` + удаляем токен из SharedPreferences → `LoginActivity` с `FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_CLEAR_TASK` (стек очищен). Если сервер недоступен, сессия всё равно стирается локально (`clearSession()`).

### 6. Лоадер / ошибка / пусто (`view_list_state.xml` + `CarListUi.render`)
Один `include` поверх RecyclerView на обоих экранах:
```kotlin
progress.isVisible = state.isLoading
errorContainer.isVisible = state.errorText != null     // текст из ТЗ + кнопка «Повторить»
tvEmpty.isVisible = state.emptyText != null            // «По вашему запросу ничего не найдено»
list.isVisible = !state.isLoading && state.errorText == null
```
- Ошибка загрузки: «Не удалось загрузить данные. Попробуйте снова.», ошибка поиска: «Не удалось выполнить поиск. Попробуйте снова.» (тексты из ТЗ) + диалог с текстом ошибки сервера (общее требование курса).
- Нет интернета → экран «Нет подключения»; когда пользователь вернётся с него, запрос **повторится сам** (`onScreenStarted()`).

## Расхождения с ТЗ, о которых стоит знать
- На макете «Результатов поиска» нет поля поиска, но в ТЗ есть «обновление списка при изменении поискового запроса». Поэтому под заголовком добавлено поле с текущим запросом — правишь его, и список обновляется.
- В ТЗ написано `BottomNavigationView` в контрольных вопросах, а в теории методички — меню на `LinearLayout`. Сделано на `BottomNavigationView` с ресурсом меню (стандартный способ).
- Иконка-закладка в нижнем меню — «Избранное» (экран из лабы 4), пока заглушка.
- «Тема», «Уведомления», «Помощь» — в ТЗ без переходов, по нажатию Snackbar «Раздел появится в следующих версиях». «Пригласи друга» — системное «Поделиться».
- «Поменять пароль» на макете есть, в ТЗ нет — сделано через письмо для сброса пароля.
- Ошибка показывается и на экране (текст из ТЗ + «Повторить»), и диалогом (общее требование курса «текст ошибки сервера в диалоговом окне»).

## Ответы на контрольные вопросы

**1. Что такое SearchView и для чего он используется?**
Виджет поля поиска: иконка лупы, поле ввода с подсказкой (`queryHint`), крестик очистки. Используется, чтобы пользователь ввёл запрос, а приложение отфильтровало или загрузило данные. У нас — поиск машин по марке/модели на «Главной» и «Результатах поиска». Основные атрибуты: `queryHint`, `iconifiedByDefault="false"` (поле сразу раскрыто, а не только иконка), `imeOptions="actionSearch"` (кнопка «Найти» на клавиатуре).

**2. Как обновлять список результатов при изменении текста в SearchView?**
Повесить `setOnQueryTextListener` и в `onQueryTextChange(newText)` передавать текст во ViewModel. ViewModel фильтрует список (локально) или делает новый запрос к серверу и кладёт результат в `StateFlow`; фрагмент подписан на него и вызывает `adapter.submitList(...)`. Чтобы не слать запрос на каждую букву — `debounce` (у нас 400 мс), а предыдущий запрос отменяется.

**3. Для чего нужны onQueryTextSubmit и onQueryTextChange?**
`onQueryTextSubmit(query)` — пользователь подтвердил ввод (нажал «Найти»/Enter): окончательный поиск. `onQueryTextChange(newText)` — вызывается при каждом изменении текста: «живой» поиск/фильтрация. Возврат `true` — событие обработано нами; `false` — пусть SearchView сделает действие по умолчанию. У нас Submit на «Главной» открывает «Результаты», а Change на «Результатах» обновляет список.

**4. Что такое RecyclerView и какие задачи он решает?**
Компонент для показа длинных и меняющихся списков/сеток. Создаёт ровно столько View, сколько помещается на экране (+ немного запаса), а при прокрутке **переиспользует** ушедшие за край ячейки для новых данных. Это экономит память и делает прокрутку плавной даже на тысячах элементов — в отличие от `LinearLayout` со всеми View сразу. Также умеет анимации добавления/удаления и разные раскладки через LayoutManager.

**5. Что такое Adapter и за что он отвечает?**
Мост между данными и RecyclerView: знает, сколько элементов, как создать View ячейки и как заполнить её данными конкретного элемента. RecyclerView сам решает, *когда* и *какую* ячейку показать, а Adapter — *что* в ней будет. У нас `CarAdapter` (на базе `ListAdapter` + `DiffUtil`).

**6. Какие методы переопределяются в адаптере и зачем?**
- `onCreateViewHolder(parent, viewType)` — создать View ячейки (inflate `item_car.xml`) и обернуть в ViewHolder. Вызывается редко — только когда переиспользовать нечего.
- `onBindViewHolder(holder, position)` — заполнить готовую ячейку данными элемента на позиции `position` (тексты, фото, обработчики кнопок). Вызывается при каждом появлении ячейки на экране.
- `getItemCount()` — сколько элементов в списке. В `ListAdapter` уже реализован (размер текущего списка), поэтому у нас его нет в коде.
- **ViewHolder** хранит ссылки на View ячейки, чтобы не делать `findViewById` при каждой прокрутке.

**7. Что такое LayoutManager и какие бывают?**
Отвечает за **расположение** элементов и прокрутку: где стоит каждая ячейка, какие видимы, какие можно переиспользовать.
- `LinearLayoutManager` — вертикальный или горизонтальный список.
- `GridLayoutManager` — сетка с заданным числом колонок (у нас: 1 на телефоне, 2–3 на планшете).
- `StaggeredGridLayoutManager` — «мозаика» с ячейками разной высоты (как в Pinterest).

**8. Для чего используется нижнее навигационное меню (BottomNavigationView)?**
Для быстрого переключения между 3–5 главными разделами приложения, доступными с любого экрана одним нажатием. Закреплено внизу (удобно большим пальцем), выбранный пункт подсвечен. У нас: Главная, Избранное, Настройки.

**9. Где описываются пункты меню для BottomNavigationView?**
В XML-ресурсе меню в папке `res/menu/` (у нас `res/menu/bottom_nav.xml`): каждый `<item>` с `android:id`, `android:icon`, `android:title`. Подключается атрибутом `app:menu="@menu/bottom_nav"` у `BottomNavigationView`. По `id` пункта в коде понимаем, какую вкладку выбрали.

**10. Как организуют переключение экранов по пунктам BottomNavigationView?**
- **Через фрагменты вручную (у нас):** одна Activity с контейнером (`FragmentContainerView`) над меню. В `setOnItemSelectedListener` по `item.itemId` делаем `supportFragmentManager.commit { replace(R.id.container, нужныйФрагмент) }`. Вложенные экраны — `replace(...)` + `addToBackStack(null)`.
- **Через Navigation Component:** экраны описываются в навигационном графе (`res/navigation/nav_graph.xml`), id пунктов меню совпадают с id экранов графа, и одна строка `bottomNav.setupWithNavController(navController)` сама переключает экраны и хранит back stack каждой вкладки.

### Могут ещё спросить
- **Зачем `DiffUtil` / `ListAdapter`, а не `notifyDataSetChanged()`?** `notifyDataSetChanged` перерисовывает всё и без анимаций. DiffUtil в фоне сравнивает старый и новый список (по `id` — тот же ли элемент, по `equals` — изменился ли) и обновляет только нужные карточки.
- **Почему фото машин в публичном бакете, а аватары — в приватном?** Каталог машин видят все, а аватар и документы — персональные данные; к приватным файлам доступ только по подписанной временной ссылке и по RLS-политике «только свой userId».
- **Что такое debounce?** Пропускает значение дальше, только если после него была пауза заданной длины. Пока пользователь печатает, запросы не уходят.
- **Зачем `SavedStateHandle`?** Хранилище ViewModel, которое сохраняется в Bundle — переживает не только поворот, но и убийство процесса системой. Аргументы фрагмента (у нас — запрос поиска) попадают туда автоматически.
- **Как фрагменты узнают, куда переходить?** Через интерфейс `MainNavigator`, который реализует `MainActivity`. Фрагмент вызывает `navigator.openProfile()` и не знает, как устроена навигация.
