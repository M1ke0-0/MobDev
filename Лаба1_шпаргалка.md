# Лаба №1 — шпаргалка (DriveNext)

## О чём лаба
Все 5 лаб — это **одно приложение DriveNext** (аренда авто), которое дописывается от лабы к лабе.
В лабе 1 делаем «вход в приложение»:

| Экран | Что делает |
|---|---|
| **Splash** (загрузка) | Название сверху слева, слоган, логотип по центру. Держится ~2 сек, потом сам переходит дальше |
| **Нет подключения** | Иконка, текст, кнопка «Повторить попытку» (с лоадером) |
| **Onboarding** (приветствие) | 3 слайда в `ViewPager2`, кнопки «Пропустить», «Далее», «Поехали», точки-индикатор |

Технологии: **SplashScreen API**, **ConnectivityManager** (проверка интернета), **ViewPager2 + Fragment + FragmentStateAdapter**, **SharedPreferences** (запомнить, что онбординг пройден).

Общие требования курса (стр. 50 методички): minSdk = Android 12 (API 31), чистая архитектура (data / domain / presentation), MVVM (вся логика во ViewModel), Git.

## Схема переходов

```
            запуск
              │
        [ SplashActivity ]  ← 2 сек
              │
     есть интернет? ── нет ──► [ NoConnectionActivity ] ──«Повторить»──┐
              │ да                    ▲   нет: Snackbar «нет сети»      │ есть сеть
              ▼                       └─────────────────────────────────┘
     онбординг пройден? ── нет ──► [ OnboardingActivity ] ──► [ LoginActivity ]
              │ да                   (Пропустить / Поехали → флаг в SharedPreferences)
              ▼
     есть access token? ── нет ──► [ LoginActivity ]  (заглушка до следующих лаб)
              │ да
              ▼
        [ MainActivity ]  (заглушка)
```

Это правило «куда идти» лежит в одном месте — `GetStartDestinationUseCase`.

**Как объяснить на защите:** зависимости смотрят «внутрь». `presentation` → `domain` ← `data`.
Domain содержит только интерфейсы (`NetworkRepository`) и правила; data их реализует; ViewModel работает через интерфейсы и не знает, что внутри SharedPreferences.

## Ключевые куски кода

### 1. SplashScreen (4 шага из методички)
1. Зависимость: `implementation("androidx.core:core-splashscreen:1.0.1")` — `app/build.gradle.kts`
2. Тема в `res/values/themes.xml`:
   ```xml
   <style name="Theme.DriveNext.Splash" parent="Theme.SplashScreen">
       <item name="windowSplashScreenBackground">@color/white</item>
       <item name="windowSplashScreenAnimatedIcon">@drawable/ic_splash_logo</item>
       <item name="postSplashScreenTheme">@style/Theme.DriveNext</item>
   </style>
   ```
3. Тема указана у стартовой Activity в `AndroidManifest.xml` (`android:theme="@style/Theme.DriveNext.Splash"`).
4. В `SplashActivity.onCreate` вызов **до** `super.onCreate()`:
   ```kotlin
   installSplashScreen()
   super.onCreate(savedInstanceState)
   ```
   Почему до: системный сплэш должен успеть настроиться и переключить тему на `postSplashScreenTheme` до того, как Activity создаст свой UI.

> Системный сплэш Android 12+ умеет показывать только иконку по центру. Макет требует название + слоган, поэтому после системного сплэша показываем свою разметку `activity_splash.xml` ещё 2 секунды.

### 2. Проверка интернета
Разрешения в манифесте:
```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
```
Код (`data/repository/NetworkRepositoryImpl.kt`):
```kotlin
val cm = context.getSystemService(Context.CONNECTIVITY_SERVICE) as ConnectivityManager
val network = cm.activeNetwork ?: return false
val caps = cm.getNetworkCapabilities(network) ?: return false
return caps.hasCapability(NetworkCapabilities.NET_CAPABILITY_INTERNET)
```

### 3. ViewPager2 (6 шагов из методички)
1. `ViewPager2` в разметке `activity_onboarding.xml`
2. Список страниц — `onboardingPages` в `OnboardingPage.kt`
3. Адаптер `OnboardingPagerAdapter : FragmentStateAdapter` — `getItemCount()` и `createFragment(position)`
4. `binding.viewPager.adapter = OnboardingPagerAdapter(this, pages)`
5. `registerOnPageChangeCallback` → сообщаем ViewModel номер страницы → меняем текст кнопки «Далее»/«Поехали» и точки
6. `setCurrentItem(position, true)` — по нажатию «Далее»

### 4. Сохранение «онбординг пройден»
`OnboardingRepositoryImpl`: `prefs.edit { putBoolean("onboarding_completed", true) }`.
Вызывается и по «Пропустить», и по «Поехали».

### 5. MVVM: как Activity общается с ViewModel
- Activity только передаёт нажатия: `btnNext.setOnClickListener { viewModel.onNextClick() }`
- ViewModel хранит состояние в `StateFlow` (номер страницы, «идёт проверка») и одноразовые события в `Channel` (навигация, snackbar)
- Activity подписывается через `repeatOnLifecycle(STARTED) { flow.collect { ... } }`
- ViewModel переживает поворот экрана — таймер сплэша и номер страницы не сбрасываются

## Как запустить и потыкать

### Установка (один раз)
1. Установи Android Studio: `brew install --cask android-studio` (или с developer.android.com).
2. Первый запуск → мастер Setup Wizard скачает Android SDK.
3. **File → Open** → выбери папку `MobDev/DriveNext`. Дождись Gradle Sync (внизу прогресс). Если предложит обновить AGP/Gradle — соглашайся.
4. **Device Manager** (справа) → **Create Virtual Device** → Pixel → образ **API 34/35** (минимум API 31).
5. Зелёная кнопка ▶ **Run 'app'**.

### Сценарии для проверки
| # | Что сделать | Что должно быть |
|---|---|---|
| 1 | Первый запуск с интернетом | Сплэш 2 сек → онбординг |
| 2 | Листать свайпом | Меняются слайды, точка-индикатор растягивается на текущем |
| 3 | Жать «Далее» | Переход на следующий слайд; на 3-м кнопка становится «Поехали» |
| 4 | «Поехали» или «Пропустить» | Экран-заглушка «Экран входа» |
| 5 | Закрыть и запустить снова | Сплэш → сразу «Экран входа» (онбординг больше не показывается) |
| 6 | Включить авиарежим (шторка эмулятора) и запустить | Сплэш → «Нет подключения» |
| 7 | Нажать «Повторить попытку» без сети | Крутится лоадер → снизу «Подключение по-прежнему отсутствует» |
| 8 | Выключить авиарежим → «Повторить попытку» | Переход дальше (онбординг или вход) |
| 9 | Повернуть экран на онбординге | Остаётся тот же слайд |

**Сбросить приложение (чтобы снова увидеть онбординг):**
- в эмуляторе: долгий тап по иконке → App info → Storage → **Clear storage**
- или в терминале Android Studio: `adb shell pm clear com.mtuci.drivenext`

## Ответы на контрольные вопросы

**1. Как создать переменную в Kotlin?**
`var` — изменяемая (`var age = 20; age = 21`), `val` — только для чтения, задаётся один раз (`val name = "Иван"`). Тип можно не писать — компилятор выведет сам: `val ok = true` → `Boolean`.

**2. Что такое Activity?**
Компонент Android, представляющий один экран с UI. Имеет жизненный цикл: `onCreate → onStart → onResume → onPause → onStop → onDestroy`. Каждую Activity нужно объявить в `AndroidManifest.xml`. У нас: `SplashActivity`, `NoConnectionActivity`, `OnboardingActivity` и т.д.

**3. Для чего нужен Intent?**
Объект-«намерение» для запуска компонентов: открыть другую Activity, сервис, передать данные. У нас: `startActivity(Intent(this, LoginActivity::class.java))`. Бывают явные (указан класс) и неявные (указано действие, например открыть ссылку).

**4. Цель SplashScreen и какие проблемы восприятия решает?**
Показывает брендированный экран, пока приложение запускается и инициализируется. Убирает белый/чёрный пустой экран при старте, скрывает задержку загрузки, даёт единообразный старт на разных устройствах.

**5. Где указывается тема SplashScreen?**
Тема (наследник `Theme.SplashScreen`) описывается в `res/values/themes.xml` и назначается стартовой (LAUNCHER) Activity в `AndroidManifest.xml` через `android:theme`. Параметр `postSplashScreenTheme` — тема, на которую переключиться после сплэша.

**6. Где в жизненном цикле инициализируется SplashScreen и почему?**
В `onCreate` стартовой Activity, **до** `super.onCreate()` и `setContentView()`. Иначе тема не успеет смениться на основную и UI отрисуется с темой сплэша / будут артефакты.

**7. Где объявляются uses-permission и что будет без нужного разрешения?**
В `AndroidManifest.xml`, внутри `<manifest>`, вне `<application>`. Без разрешения вызов упадёт с `SecurityException` (например, `getNetworkCapabilities` без `ACCESS_NETWORK_STATE`), а сетевые запросы без `INTERNET` не выполнятся.

**8. INTERNET vs ACCESS_NETWORK_STATE?**
`INTERNET` — чтобы **выполнять** сетевые запросы (открывать сокеты, ходить на сервер). `ACCESS_NETWORK_STATE` — чтобы **узнавать состояние** сети (есть ли подключение, Wi‑Fi или мобильная) через `ConnectivityManager`. Оба «normal» — выдаются автоматически при установке, спрашивать пользователя не нужно.

**9. Что такое AndroidManifest.xml?**
Главный файл-описание приложения для системы: package/namespace, список всех Activity (и какая стартовая — `intent-filter` с `MAIN`/`LAUNCHER`), разрешения, класс Application, иконка, название, тема.

**10. Что такое Fragment и чем отличается от Activity?**
Fragment — переиспользуемая часть интерфейса со своим макетом и жизненным циклом, но живёт **внутри** Activity и не может существовать сам по себе. Activity — самостоятельный экран, объявляется в манифесте; Fragment — нет. В одной Activity может быть несколько фрагментов. У нас каждый слайд онбординга — `OnboardingPageFragment` внутри `OnboardingActivity`.

### Могут ещё спросить
- **Зачем ViewModel?** Хранит состояние экрана и логику, переживает поворот экрана; Activity остаётся «тонкой».
- **Что такое FragmentStateAdapter?** Адаптер для ViewPager2, который создаёт фрагменты по позиции и сам управляет их жизненным циклом (лишние уничтожает, состояние сохраняет).
- **ViewPager vs ViewPager2?** ViewPager2 построен на RecyclerView, поддерживает вертикальную прокрутку, RTL, корректнее работает с жизненным циклом фрагментов, у него удобный `registerOnPageChangeCallback`.
- **Где хранится флаг онбординга?** В SharedPreferences — файл ключ‑значение в приватной папке приложения; удаляется при очистке данных/удалении приложения.
- **Зачем `_binding = null` в `onDestroyView` фрагмента?** View фрагмента уничтожается раньше самого фрагмента; без обнуления будет утечка памяти.
