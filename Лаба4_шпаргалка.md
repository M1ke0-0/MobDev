# Лаба №4 — шпаргалка (DriveNext)

## О чём лаба
Продолжаем то же приложение. В лабе 4 оживают кнопки «Детали», «Забронировать», вкладка «Избранное» и пункт «Мои бронирования». Главная тема по теории — **хранение данных на устройстве**: **SharedPreferences** и **Room**.

| Экран | Класс | Что делает |
|---|---|---|
| **Детали** | `CarDetailsFragment` | Фото, «Марка Модель», адрес, описание, цена/день, «Забронировать». Сердечко — добавить/убрать из избранного (иконка меняет цвет). Лоадер и ошибка при загрузке |
| **Оформление аренды** | `BookingFragment` | Карточка машины, даты начала/конца (выбор в календаре), адрес, аренда и страховка за период, итог, депозит, «Продолжить» |
| **Удачной поездки** | `BookingSuccessActivity` | «Бронирование успешно создано», кнопки «Перейти к своим бронированиям» и «Домой» |
| **Мои бронирования** | `MyBookingsFragment` | Список: активные (дата и время начала) и завершённые (дата окончания) |
| **Бронирование #N** | `BookingDetailsFragment` | Номер, машина, адрес, даты, ФИО, номер ВУ, статус, суммы, «Отменить бронирование» |
| **Избранное** | `FavoritesFragment` | Карточки избранных машин с кнопками «Забронировать» и «Детали» |

**Где что хранится:**
- **Сервер (Supabase)** — каталог машин. Добавили колонки `address` и `description` (для «Деталей»).
- **Room (локальная БД)** — избранное (таблица `favorites`) и бронирования (таблица `bookings`).
- **SharedPreferences** — флаг «онбординг пройден» (сделано ещё в лабе 1, `OnboardingRepositoryImpl`).

```

 │                                                                        │
 │  Главная / Поиск / Избранное                                           │
 │     ├─ «Детали» ──────────► Детали ──♥──► таблица favorites (Room)     │
 │     │                         │                                        │
 │     └─ «Забронировать» ───────┴──«Забронировать»──► Оформление аренды  │
 │                                                          │             │
 │  Настройки ─ «Мои бронирования» ─► Мои бронирования ◄────┼───┐         │
 │                                         │                │   │         │
 │                          (активное) ────► Бронирование #N    │         │
 │                                     «Отменить» → назад к списку        │
 │                                                          │   │         │
 │  [ 🏠 Главная | 🔖 Избранное | ⚙ Настройки ]              │   │         │
 └──────────────────────────────────────────────────────────┼───┼─────────┘
                                «Продолжить» (стек очищен)   ▼   │
                                 ┌──── BookingSuccessActivity ───┐
                                 │ «Перейти к своим бронированиям»──► новая MainActivity
                                 │ «Домой» ─────────────────────────► новая MainActivity
                                 └───────────────────────────────┘     (Главная)
```

- Все новые экраны, кроме «Удачной поездки», — **фрагменты**, которые кладутся поверх вкладки через `push()` (с `addToBackStack`), как «Результаты поиска» в лабе 3.
- «Удачной поездки» — **отдельная Activity** с флагами `NEW_TASK | CLEAR_TASK`. Это и есть «очистка стека навигации» из ТЗ: после неё «Назад» не вернёт на оформление аренды.
- «Перейти к своим бронированиям» открывает `MainActivity` с extra `open_bookings = true`. Activity показывает «Главную» и поверх неё «Мои бронирования», поэтому «Назад» оттуда ведёт на главную.

## Ключевые куски кода

### 1. Room: Entity (`data/local/BookingEntity.kt`)
```kotlin
@Entity(tableName = "bookings")          // класс = таблица
data class BookingEntity(
    @PrimaryKey(autoGenerate = true) val id: Long = 0L,   // номер бронирования, Room ставит сам
    val carId: String,
    val brand: String,
    ...
    val startAt: Long,      // даты — секунды с 1970 года: Room хранит только простые типы
    val endAt: Long,
    val driverName: String,
    val licenseNumber: String
)
```
Каждое поле — колонка, каждый объект — строка. В `FavoriteCarEntity` первичный ключ — `carId` (`@PrimaryKey` без autoGenerate), поэтому одну машину нельзя добавить в избранное дважды.

### 2. Room: DAO (`data/local/FavoriteDao.kt`)
```kotlin
@Dao
interface FavoriteDao {
    @Query("SELECT * FROM favorites ORDER BY addedAt DESC")
    fun getAll(): Flow<List<FavoriteCarEntity>>        // Flow — Room сам пришлёт новый список после изменений

    @Query("SELECT EXISTS(SELECT 1 FROM favorites WHERE carId = :carId)")
    fun isFavorite(carId: String): Flow<Boolean>       // для цвета сердечка

    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun insert(car: FavoriteCarEntity)         // suspend — не на главном потоке

    @Query("DELETE FROM favorites WHERE carId = :carId")
    suspend fun delete(carId: String)
}
```
Room **сам генерирует реализацию** этого интерфейса во время сборки. Для этого нужен KSP и `ksp("androidx.room:room-compiler")`.

### 3. Room: база данных (`data/local/AppDatabase.kt`)
```kotlin
@Database(entities = [FavoriteCarEntity::class, BookingEntity::class], version = 1)
abstract class AppDatabase : RoomDatabase() {
    abstract fun favoriteDao(): FavoriteDao
    abstract fun bookingDao(): BookingDao

    companion object {
        @Volatile private var INSTANCE: AppDatabase? = null

        fun getInstance(context: Context): AppDatabase {
            return INSTANCE ?: synchronized(this) {       // только один поток создаёт базу
                val instance = Room.databaseBuilder(context.applicationContext,
                    AppDatabase::class.java, "drivenext_db").build()
                INSTANCE = instance
                instance
            }
        }
    }
}
```
Это код почти один в один из методички. Базу создаёт `AppContainer`: `AppDatabase.getInstance(context)`.

### 4. Сердечко в «Деталях» (`CarDetailsViewModel` + `CarDetailsFragment`)
```kotlin
// ViewModel: подписка на «есть ли машина в избранном»
favorites.isFavorite(carId).collect { favorite -> _state.update { it.copy(isFavorite = favorite) } }

fun onFavoriteClick() {
    ...
    try {
        if (current.isFavorite) favorites.remove(car.id) else favorites.add(car)
    } catch (e: Exception) {
        _events.send(CarDetailsEvent.FavoriteFailed)   // → Snackbar «Не удалось добавить в избранное…»
    }
}
```
```kotlin
// Fragment: иконка зависит от состояния
favoriteItem.setIcon(if (state.isFavorite) R.drawable.ic_favorite else R.drawable.ic_favorite_border)
```
После нажатия меняется таблица → Room присылает новое значение во Flow → иконка перекрашивается. Вкладка «Избранное» тоже подписана на Flow, поэтому обновляется сама.

### 5. Расчёт стоимости (`domain/model/Booking.kt`)
```kotlin
fun calculate(pricePerDay: Int, start: LocalDateTime, end: LocalDateTime): BookingPrice {
    val days = maxOf(1, Duration.between(start, end).toDays().toInt())
    return BookingPrice(days = days, rent = pricePerDay * days, insurance = INSURANCE_PER_DAY * days)
}
// total = rent + insurance,  INSURANCE_PER_DAY = 300,  DEPOSIT = 15000
```
Пример из макета: 2500 × 3 + 300 × 3 = **8400₽**, депозит 15000₽.

### 6. Выбор дат (`BookingFragment.showDatePicker`)
```kotlin
MaterialDatePicker.Builder.dateRangePicker()                       // выбор периода «с — по»
    .setSelection(Pair(startDay * DAY_MS, endDay * DAY_MS))
    .setCalendarConstraints(CalendarConstraints.Builder()
        .setValidator(DateValidatorPointForward.now()).build())   // прошлые даты нельзя
```
- Календарь возвращает миллисекунды (полночь UTC); делим на `DAY_MS` и получаем номер дня (`epochDay`).
- Номера дней хранятся в `SavedStateHandle`, поэтому даты переживают поворот экрана.
- Время выдачи всегда 08:00.

### 7. «Продолжить» → сохранение бронирования (`BookingViewModel.onContinueClick`)
```kotlin
val profile = getProfile.profile.value ?: getProfile.refresh().getOrNull()  // ФИО и № ВУ из профиля
bookingRepository.create(Booking(id = 0L, car = car, start = ..., end = ...,
    driverName = profile?.fullName.orEmpty(), licenseNumber = profile?.licenseNumber.orEmpty()))
_events.send(BookingEvent.OpenSuccess)     // → MainActivity.openBookingSuccess() → Activity с CLEAR_TASK
```
Флаг `isSaving` защищает от двойного нажатия, иначе получилось бы два бронирования.

### 8. Активные и завершённые (`Booking.isActive`, `BookingAdapter`)
```kotlin
fun isActive(now: LocalDateTime = LocalDateTime.now()) = end.isAfter(now)
```
- Активное: «Начало аренды: 08:00, 27 сентября 2024», по нажатию открываются детали.
- Завершённое: «Аренда завершена, 30 сентября 2024», не нажимается.
- В деталях статус «Одобрено» или «Завершено», кнопка «Отменить» видна только у активного.

### 9. Отмена бронирования (`BookingDetailsViewModel.onCancelClick`)
```kotlin
bookingRepository.cancel(bookingId)        // DELETE FROM bookings WHERE id = :id
_events.send(BookingDetailsEvent.Close)    // фрагмент делает «Назад» → список «Мои бронирования»
```
Список подписан на Flow из Room, поэтому отменённое бронирование исчезает из него само.

### 10. Передача машины между экранами
- В «Детали» передаётся только `carId` (`bundleOf("car_id" to id)`), а сама машина загружается с сервера. Так требует ТЗ: лоадер и ошибка загрузки.
- В «Оформление аренды» передаётся весь объект `Car`: он `Serializable`, поэтому кладётся в `Bundle`. ViewModel достаёт его через `SavedStateHandle`.

## Ответы на контрольные вопросы

**1. Что такое SharedPreferences и для чего он используется?**
Встроенное хранилище Android для небольших данных в виде пар «ключ — значение». Данные сохраняются в XML-файле в папке приложения и переживают перезапуск. Подходит для настроек и флагов. У нас в нём хранится флаг «онбординг пройден» (`OnboardingRepositoryImpl`).

**2. Какие типы данных поддерживает SharedPreferences?**
`Boolean`, `Int`, `Long`, `Float`, `String` и `Set<String>`. Только примитивы и строки, объекты напрямую не сохранить.

**3. Какие методы используются для записи через Editor?**
`prefs.edit()` возвращает Editor. Дальше `putBoolean/putInt/putLong/putFloat/putString/putStringSet(key, value)`, `remove(key)`, `clear()` и в конце `apply()` или `commit()`. В Kotlin есть сокращение `prefs.edit { putBoolean(KEY, true) }` из core-ktx.

**4. Чем apply() отличается от commit()?**
- `apply()` сохраняет на диск **асинхронно**, ничего не возвращает и не блокирует поток.
- `commit()` пишет **синхронно** и возвращает `Boolean`: удалось или нет.
- Обычно используют `apply()`. `commit()` нужен, если результат важен сразу: например, в `resetAppData()` мы вызываем `edit(commit = true)`.

**5. Что такое Room и какую задачу он решает?**
Библиотека Jetpack, обёртка над SQLite. Даёт типобезопасный доступ к базе: запросы проверяются при сборке, код DAO генерируется автоматически, поддерживаются `suspend` и `Flow`. Нужна, чтобы хранить структурированные данные между запусками без сервера. У нас это избранное и бронирования.

**6. Что такое Entity и как она связана с таблицей?**
Класс с аннотацией `@Entity`, описывающий таблицу. Поля класса — колонки, объект — одна строка. `tableName` задаёт имя таблицы, `@PrimaryKey` — первичный ключ. У нас это `FavoriteCarEntity` (таблица favorites) и `BookingEntity` (bookings).

**7. Что такое DAO и для чего он нужен?**
Data Access Object — интерфейс с методами доступа к данным: чтение, вставка, удаление. Мы пишем только сигнатуры с аннотациями, а реализацию Room генерирует сам. У нас это `FavoriteDao` и `BookingDao`.

**8. Основные аннотации Room?**
- `@Entity` — таблица; `@PrimaryKey(autoGenerate = true)` — ключ; `@ColumnInfo(name = ...)` — другое имя колонки.
- `@Dao` — интерфейс доступа; `@Query("SQL")` — произвольный запрос.
- `@Insert(onConflict = ...)`, `@Update`, `@Delete` — изменение данных.
- `@Database(entities = [...], version = N)` — класс базы.

**9. Как создают экземпляр базы через Room.databaseBuilder?**
`Room.databaseBuilder(context.applicationContext, AppDatabase::class.java, "имя_файла").build()`. Берём `applicationContext`, чтобы не держать ссылку на Activity и не получить утечку памяти. Создаём один раз (singleton) — см. `AppDatabase.getInstance`.

**10. Зачем synchronized при создании singleton?**
Если два потока одновременно вызовут `getInstance`, оба могут увидеть `INSTANCE == null` и создать две базы. `synchronized(this)` пускает в блок только один поток, второй ждёт и уже получает готовый экземпляр. `@Volatile` нужен, чтобы все потоки сразу видели записанное значение `INSTANCE`.

### Могут ещё спросить
- **Почему DAO-методы `suspend`?** Room запрещает обращаться к базе в главном потоке, иначе интерфейс подвиснет. С `suspend` Room сам выполняет запрос в фоновом потоке.
- **Зачем `Flow` в DAO?** Чтобы экран обновлялся сам: при любом изменении таблицы Room заново выполняет запрос и присылает новый список. Поэтому «Избранное» и «Мои бронирования» обновляются без ручной перезагрузки.
- **Что такое KSP?** Kotlin Symbol Processing — генератор кода во время сборки. Room через него создаёт классы `AppDatabase_Impl` и `FavoriteDao_Impl`.
- **Зачем `version = 1`?** Это версия схемы. Если поменять Entity (например, добавить поле), версию нужно увеличить и описать миграцию, иначе приложение упадёт на старой базе.
- **Чем Room лучше SharedPreferences для бронирований?** Бронирования — список объектов со многими полями, по ним нужны выборки (сортировка, поиск по id, удаление). SharedPreferences для этого не предназначен.
- **Как «очищается стек» после бронирования?** `Intent` с флагами `FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_CLEAR_TASK`: все прежние Activity закрываются, новая становится единственной.
