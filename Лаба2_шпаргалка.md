# Лаба №2 — шпаргалка (DriveNext)

## О чём лаба
Продолжаем то же приложение. В лабе 2 делаем **вход и регистрацию**:

| Экран | Что делает |
|---|---|
| **Вход/регистрация** (`AuthChoiceActivity`) | Название, слоган, логотип, кнопки «Войти» и «Зарегистрироваться» |
| **Вход в аккаунт** (`LoginActivity`) | Email + пароль (глазик), «Войти» (активна, когда заполнены оба поля), «Войти через Google», «Забыли пароль?», «Зарегистрироваться» |
| **Регистрация, шаг 1** | Email, пароль, повтор пароля, чекбокс согласия |
| **Регистрация, шаг 2** | Фамилия, имя, отчество (необяз.), дата рождения, пол |
| **Регистрация, шаг 3** | Фото профиля (необяз.), номер ВУ (10 цифр), дата выдачи, фото ВУ и паспорта (галерея или камера) |
| **Успешная регистрация** | «Поздравляем», «Далее» → главный экран с очисткой стека |

Технологии из методички: **MaterialDatePicker**, **Activity Result API** (`PickVisualMedia`, `TakePicture`), **FileProvider**, **Supabase** (Auth + Postgrest + Storage).

## Схема переходов

```
 Splash ──► Onboarding ──► [ AuthChoice ] ──«Войти»──► [ Login ] ──успех──► Main (стек очищен)
                                │                         │  «Зарегистрироваться»
                                └──«Зарегистрироваться»──►├──────────────┐
                                                          ▼              ▼
                                         [ RegistrationActivity: шаг 1 → шаг 2 → шаг 3 ]
                                                                           │ успех
                                                                           ▼
                                              [ RegistrationSuccess ] ──«Далее»──► Main (стек очищен)

 Нет интернета при запросе ──► [ NoConnection ] ──сеть появилась──► назад к той же форме (поля на месте)
```

**Архитектура (для защиты):**
- Валидация (email `.com/.ru`, даты, 10 цифр) — в `domain/validation`, это бизнес-правила, они не знают про Android.
- Use case сначала проверяет интернет (`NetworkRepository`), потом вызывает репозиторий. Все ошибки → `Result.failure(AppError)`.
- `AuthRepositoryImpl` — единственное место, которое знает про Supabase. Исключения библиотеки переводятся в `AppError` (`ErrorMapper`), поэтому ViewModel не зависит от Supabase.
- ViewModel превращает `AppError` в текст (`UiText`) → Activity показывает **диалог**. `AppError.NoConnection` → экран «Нет подключения».
- Три шага регистрации — **фрагменты в одной Activity с общей ViewModel** (`activityViewModels()`). Поэтому «Назад» возвращает на предыдущий шаг с заполненными полями, а данные всех шагов собираются в один `RegistrationData`.

## Ключевые куски кода

### 1. MaterialDatePicker (`presentation/common/DateInput.kt`)
```kotlin
val picker = MaterialDatePicker.Builder.datePicker()
    .setTitleText("Дата рождения")
    .setCalendarConstraints(constraints)        // только прошедшие даты
    .build()
picker.addOnPositiveButtonClickListener { selectedDateUtcMillis ->
    val date = Instant.ofEpochMilli(selectedDateUtcMillis).atZone(ZoneOffset.UTC).toLocalDate()
}
picker.show(childFragmentManager, "birth_date_picker")
```
- Открывается по иконке календаря в `TextInputLayout` (`setStartIconOnClickListener`).
- Дату можно и ввести руками: `DateMaskWatcher` сам ставит слэши → `DD/MM/YYYY`.
- **Почему через UTC:** пикер возвращает полночь выбранного дня по UTC. Если перевести в локальное время, в поясах «западнее Гринвича» получится предыдущий день.
- После поворота экрана слушатель теряется → `reattachDatePicker` находит открытый пикер по тегу и вешает слушатель снова.

### 2. Фото из галереи и с камеры (`RegisterStep3Fragment.kt`)
```kotlin
// Галерея: разрешение READ_MEDIA_IMAGES не нужно, доступ выдаётся через Uri
private val pickOneImage = registerForActivityResult(ActivityResultContracts.PickVisualMedia()) { uri: Uri? -> ... }
pickOneImage.launch(PickVisualMediaRequest(ActivityResultContracts.PickVisualMedia.ImageOnly))

// Камера: пишет снимок в заранее подготовленный Uri, возвращает true/false
private val takeOnePhoto = registerForActivityResult(ActivityResultContracts.TakePicture()) { success: Boolean -> ... }
val uri = FileProvider.getUriForFile(context, "${context.packageName}.fileprovider", file)
takeOnePhoto.launch(uri)
```
FileProvider объявлен в манифесте (`<provider>` + `res/xml/file_paths.xml`). Uri снимка хранится в `SavedStateHandle` ViewModel — переживёт даже убийство процесса, пока открыта камера.

### 3. Supabase (`data/remote/SupabaseProvider.kt`, `AuthRepositoryImpl.kt`)
```kotlin
createSupabaseClient(BuildConfig.SUPABASE_URL, BuildConfig.SUPABASE_KEY) {
    install(Auth) { scheme = "drivenext"; host = "login-callback"; flowType = FlowType.PKCE }
    install(Postgrest)
    install(Storage)
}
```
- **Вход:** `auth.signInWith(Email) { email = …; password = … }` → access token сохраняем в SharedPreferences (по нему сплэш решает, пускать ли сразу на главный).
- **Регистрация:** `auth.signUpWith(Email)` → загрузка фото в бакет `documents/<userId>/…` → `postgrest["users"].upsert(UserProfileDto(...))`.
- **Google:** `auth.signInWith(Google)` открывает браузер → после входа браузер открывает `drivenext://login-callback?code=…` → `LoginActivity` (singleTask, `onNewIntent`) → `auth.exchangeCodeForSession(code)`.
- **Забыли пароль:** `auth.resetPasswordForEmail(email)`.

### 4. Кнопки активны только при заполненных полях
Состояние экрана — `data class` в `StateFlow`, у него вычисляемые свойства:
```kotlin
val isSignInEnabled get() = email.isNotBlank() && password.isNotEmpty() && !isLoading
```
Activity в `render(state)` просто делает `btnSignIn.isEnabled = state.isSignInEnabled`.

## Настройка Supabase (обязательно, иначе при входе будет «Сервер не настроен»)

1. supabase.com → **New project**.
2. **SQL Editor** → вставить содержимое `DriveNext/supabase/schema.sql` → **Run**. Создадутся таблица `users`, приватный бакет `documents` и политики доступа.
3. **Authentication → Sign In / Providers → Email**: включён; **Confirm email — выключить** (иначе после регистрации нет сессии и приложение попросит подтвердить почту).
4. **Project Settings → API**: скопировать **Project URL** и **anon public key** в `DriveNext/local.properties`:
   ```
   supabase.url=https://xxxxxxxx.supabase.co
   supabase.key=eyJhbGciOi...
   ```
5. В Android Studio: **Sync Project with Gradle Files** → Run.

**Вход через Google (по желанию, дольше настраивать):**
1. Google Cloud Console → APIs & Services → Credentials → **OAuth client ID** типа *Web application*; в Authorized redirect URIs добавить `https://xxxxxxxx.supabase.co/auth/v1/callback`.
2. Supabase → Authentication → Providers → **Google** → включить, вставить Client ID и Secret.
3. Supabase → Authentication → **URL Configuration → Redirect URLs** → добавить `drivenext://login-callback`.

## Расхождения с ТЗ, о которых стоит знать
- В ТЗ шага 2 формат даты рождения указан как `MM/DD/YYYY`, но в макете и на шаге 3 — `DD/MM/YYYY`. Сделано везде `DD/MM/YYYY` (как в макете, привычно для России).
- «Забыли пароль?» есть в макете, но не в ТЗ — сделано через `resetPasswordForEmail`.
- Кнопка «Далее» на шагах 2 и 3 неактивна, пока не заполнены обязательные поля (по ТЗ). Поэтому «Пожалуйста, заполните все обязательные поля.» появится, только если ввести одни пробелы.
- Supabase-kt тянет `androidx.browser:1.9.0`, которому нужен compileSdk 36 — в `app/build.gradle.kts` версия зафиксирована на 1.8.0. Kotlin поднят до 2.2.21 (нужен для supabase-kt 3.2.6).
- `Lint` (Analyze → Inspect / `gradle lint`) падает из‑за несовместимости старого lint в AGP 8.7 с lifecycle 2.9 — на сборку и запуск не влияет.

## Ответы на контрольные вопросы

**1. Что такое MaterialDatePicker и для чего он применяется?**
Диалог выбора даты (или диапазона дат) из библиотеки Material Components в стиле Material Design. Даёт единый вид на всех устройствах, календарь и ручной ввод, ограничения на даты. У нас — выбор даты рождения и даты выдачи ВУ.

**2. Какие шаги нужны, чтобы создать MaterialDatePicker через Builder и задать заголовок?**
`MaterialDatePicker.Builder.datePicker()` → `.setTitleText("Дата рождения")` → по желанию `.setSelection(ms)`, `.setCalendarConstraints(...)` → `.build()`.

**3. Как показать его на экране через supportFragmentManager?**
`picker.show(supportFragmentManager, "date_picker")`. Пикер — это `DialogFragment`, поэтому показывается через FragmentManager с тегом (во фрагменте — `childFragmentManager`). По тегу его потом можно найти, например после поворота.

**4. Для чего addOnPositiveButtonClickListener?**
Колбэк на нажатие «OK»: в него приходит выбранное значение. Здесь мы переводим его в дату и записываем в поле. Есть также `addOnNegativeButtonClickListener`, `addOnCancelListener`, `addOnDismissListener`.

**5. Что означает selectedDateUtcMillis?**
Выбранная дата в миллисекундах с 01.01.1970 — **полночь этого дня по UTC**. Поэтому переводить в дату нужно в поясе UTC (`atZone(ZoneOffset.UTC)`), иначе в некоторых часовых поясах получится соседний день.

**6. Что такое Uri и почему его получает приложение при выборе изображения?**
Uri — унифицированный адрес ресурса (`content://...`). Системный пикер не отдаёт файл или путь к нему: он выдаёт Uri с временным разрешением на чтение именно этого файла. Так приложению не нужен доступ ко всей галерее, а файл читается через `contentResolver.openInputStream(uri)`.

**7. Для чего Activity Result API и зачем registerForActivityResult?**
Современная замена `startActivityForResult/onActivityResult`: запуск другого экрана (камера, галерея) и получение результата в колбэк. `registerForActivityResult(контракт) { результат -> }` регистрирует обработчик заранее (до `STARTED`), чтобы результат был доставлен даже если Activity пересоздалась, пока пользователь был в камере. Возвращает launcher, который запускается через `launch(...)`.

**8. Что делает ActivityResultContracts.PickVisualMedia?**
Открывает системный Photo Picker для выбора одного фото/видео. Параметр `PickVisualMediaRequest(ImageOnly)` — только изображения. Результат — `Uri?` (null, если пользователь ничего не выбрал). Разрешения на чтение хранилища не требуются.

**9. Что делает ActivityResultContracts.TakePicture и что возвращает?**
Запускает приложение камеры и просит сохранить снимок по переданному Uri. Возвращает `Boolean`: `true` — снимок сохранён в этот Uri, `false` — пользователь отменил.

**10. Зачем нужен FileProvider при съёмке камерой?**
Камера — другое приложение, у неё нет доступа к приватным папкам нашего приложения, а передавать `file://` пути между приложениями на Android 7+ запрещено (`FileUriExposedException`). FileProvider выдаёт безопасный `content://` Uri на конкретный файл и временно даёт камере право записи в него.

### Могут ещё спросить
- **Зачем общая ViewModel для трёх шагов?** Данные всех шагов нужны вместе для одного запроса регистрации, и при «Назад» поля должны остаться заполненными. `activityViewModels()` даёт один экземпляр на Activity.
- **Где хранится токен?** Supabase сам сохраняет сессию (и обновляет access token по refresh token). Дополнительно access token кладём в SharedPreferences — по нему сплэш решает, пускать ли сразу на главный экран.
- **Что такое RLS?** Row Level Security в PostgreSQL: правила, какие строки может читать/менять пользователь. У нас `auth.uid() = id` — каждый видит только свой профиль и свои фото. anon key при этом можно хранить в приложении.
- **Что такое PKCE?** Защищённый вариант OAuth: приложение генерирует секрет (code verifier), а Google возвращает одноразовый код, который обменивается на сессию только вместе с этим секретом. Перехватить код бесполезно.
- **Почему «Успешная регистрация» и главный открываются с очисткой стека?** `FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_CLEAR_TASK` — после регистрации/входа «Назад» не должна возвращать на формы.
